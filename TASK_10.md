# TASK_10 — One transactional project document and usable linked editing

Prerequisite: TASK_09. Read AGENTS.md. Preserve the existing editor workflow and project compatibility.

## Review findings (baseline 0c6b8f1)
- `core/history.py:ProjectSession` tracks only core.Project, but `ui/main_window.py:_project_document` serializes a separate mutable `bin_controller.assets`. An import with no placed clip can modify the saved document without setting dirty, enabling Save or prompting before New/Close. Relink updates composition sources through history but modifies the bin/path separately (`_relink_asset_to`, `_replace_bin_asset`); undo can restore old stream metadata with the new file, and an identical-stream relink is not dirty. The existing test `test_a_relink_to_an_identical_file_changes_the_media_not_the_composition` explicitly permits the latter behaviour; preserve its distinction between composition and media, but revise the document-level expectations.
- `_ensure_sources` calls session.apply repeatedly, and `_find_free_track` calls _apply(AddTrackCommand) before _place_selected_streams adds a clip. One user action can produce several history entries and leave tracks/source registrations after placement fails.
- `core/commands.py:SplitClipCommand.apply` copies the same link_group to both halves of every member. All four clips remain linked after splitting an A/V pair; moving the right half moves the left half, and a subsequent split can be refused because disjoint pieces cannot all contain the split point. `test_linked_split_splits_all_members_atomic` currently asserts this undesirable result.
- `validate_project` checks clip IDs but not duplicate track IDs/source keys, placeability of referenced sources, etc. A loaded or proposed invalid state should not become a valid edit history baseline.

## Implement
1. Define an immutable document snapshot containing the composition and the media catalogue (including stable asset IDs, recorded path/identity, probe metadata). Keep navigation, transient online status, pending jobs and UI selection outside it. Do not add Qt/filesystem logic to core. A higher-level project/document module may wrap existing pure Project/commands; do not rewrite every domain class or import media into core merely to combine ownership.
2. Make the session/history operate on the entire persistent document, or provide an equivalent coordinated transaction mechanism with a single saved baseline. Media bin is a projection of that state, not a second authoritative mutable catalogue. Import, relink and any future persistent relationship edit use this boundary. Relink probes/validates first, then atomically changes both catalogue and registered sources; undo/redo restores both. A path-only change is dirty even when the composition is unchanged. Ensure runtime availability is recomputed after undo/redo and remains independent of persisted identity.
3. Implement a pure composite transaction for placing streams (registration, track allocation, clip creation). Compute on a candidate snapshot; publish once or not at all. Exactly one history entry for one intentional action. Failed edits leave selection, clips, tracks, catalogue, history and dirty state intact. Reuse ImportGroupCommand where practical. Do not silently suppress unrelated CommandError.
4. On splitting a linked group, keep the original group on all left pieces and assign ONE new stable group ID to all right pieces; single-member groups may normalize to unlinked. Preserve left clip IDs, exact times and rates, and atomic failure. Undo/redo must preserve both group identities. Keep existing reject-if-incompatible fade and staggered-group policy for now.
5. Strengthen validation at document load and command commit: unique track/clip IDs and source keys, resolved catalogue references, valid source ranges and placeability, track type, fades and no same-track overlap. Missing-on-disk assets are valid references with unavailable status, not structural corruption. Give precise diagnostic errors. Retain the current project schema if possible; if changed, provide explicit migration for v1/other existing schemas and tests, not a destructive rewrite.

## Acceptance
- Import an asset but place no clips; dirty, Save, undo/redo, New/Close confirmation, autosave and reopen all behave consistently. Import failure does not dirty.
- Relink with identical streams and with accepted changed metadata; undo and redo restore the corresponding path, identity and source metadata together; save/reopen preserves exactly the document selected by history.
- Place a single stream requiring a new track and a multi-stream group; one undo reverses the action; deliberately invalid placement creates no orphan registration or track.
- Split a linked pair, independently move/split the right pair again, and verify the left remains unchanged. Check undo/redo IDs and save/reopen. Update the old single-group assertion explicitly.
- Corrupt project fixtures with duplicate IDs/keys, unknown streams, invalid source bounds; reject without altering the currently open document. Run core and GUI suites. Document the new transaction API for future assisted edits.
