# TASK_13 — Cancellable media jobs, session isolation and deterministic shutdown

Prerequisite: TASK_12. This is a reliability milestone; do not add alignment workers yet.

## Review findings (baseline 0c6b8f1)
- `media/importer.py` creates one daemon thread per file. ImportJob.process is never assigned; probe_file calls blocking subprocess.run. cancel() sets a flag but cannot cancel FFprobe; completed jobs remain in _jobs forever. A commit description claims a bounded import queue, but this implementation is not bounded.
- `ui/media_bin.py:reset` clears job mappings, but finalize_finished accepts unknown job IDs. A queued completion from the previous project can import into the new project or remove a new request's path placeholder.
- `render/exporter.py:_run` blocks reading stdout lines and only reads stderr after wait. A child can block on a full stderr pipe; a stalled child that emits no progress cannot be cancelled promptly. Tool validation/probing is also blocking. _scaled_progress maps each piece over all remaining progress, then final join starts from zero; progress may jump backwards or show 100% early.
- `ui/render_worker.py:StillWorker` uses an unsynchronised cross-thread mailbox (read then clear _pending can lose a newer request), cannot interrupt an in-flight subprocess, and shutdown ignores whether the thread actually stopped after a timeout. `main_window.py:closeEvent` likewise ignores export wait failure. `_shutdown_preview` does not cancel/join imports. docs/progress.md explicitly records unresolved QThread destruction/SIGSEGV on quit.
- Cache hit in `_request_still` bypasses generation increment, so a previously requested frame can arrive after a cached frame and replace it. Session changes must invalidate all outstanding requests, not just cache data.

## Implement
1. Provide a small shared subprocess runner (stdlib, no Qt): bounded output capture/drain stdout and stderr concurrently, monotonic timeout and cancellation event checked independently of progress, terminate then kill and reap child, clean owned artifacts, one terminal result per job. Prefer threads with bounded queues or selectors on Linux; avoid unbounded buffering of media. Use it for import probes, export, still/PTS requests and other affected background work. Reuse existing good helpers rather than introducing a task framework. Never run heavy media I/O in the GUI thread (including relink probe and source extraction; move those calls to workers).
2. Use a bounded import executor/queue, cancellation tokens and job ownership; remove completed jobs, distinguish queued/running/finished. Connect completions to a session epoch and job ID; ignore unknown/stale IDs before changing any bin/path/UI state. Cancellation of old jobs cannot cancel or finalize new ones.
3. Make still/decoration/preview requests immutable, epoch- and generation-tagged, with a synchronized latest-request mailbox (lock around take/replace, or queue). Invalidate generation on cache hit, edit, relink, New/Open/close and mode change as appropriate. Ensure a stale result cannot change visible state, even if the current result is cached or the new project has no media. Coalesce wakeups; cancel superseded expensive subprocesses when practical.
4. Define explicit owner-driven shutdown: stop timers and accept no new work, cancel all jobs, disconnect/gate late callbacks, reap children and join workers, release players and then destroy Qt objects/cache. Idempotent. Never destroy a running QThread or pretend a wait timeout succeeded; defer close with clear status if a worker cannot yet be joined. No reliance on __del__ or interpreter shutdown order.
5. Make progress monotonic and phase-aware for chunk render and join; weighted piece durations or explicit phase labels, 100% only after validation/publication. Cancellation works even with silent/stderr-heavy subprocesses and during verification.

## Acceptance
- Fake executable that emits no stdout, hangs, floods stderr or ignores TERM; cancel within an explicit test bound (e.g. two seconds plus bounded kill escalation), no deadlock/child leak, terminal signal exactly once. No destination publication on cancel.
- Queue dozens of imports; concurrency stays within configured budget, cancel queued/running jobs, job registry returns to bounded size. Open/New during import including same-path reimport; deliberately deliver queued stale success/failure and confirm new session untouched.
- Rapid scrub A -> B (cached) while A is in flight, rapid source steps, edit/relink while a decode is in flight; only newest valid result displayed. Test mailbox interleaving with barriers, not timing luck.
- Close during import, render, preview, source decode and decoration; verify every worker and process stops, cache cleanup happens after workers, no late updates. Run a subprocess-based repeated offscreen GUI open/edit/close test (at least 20 iterations); also run on actual desktop if available and report exit codes. Do not claim the existing shutdown defect resolved unless repeated checks pass.
- Existing tests, including real FFmpeg cancellation, pass. Record remaining environment-specific limits.
