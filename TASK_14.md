# TASK_14 — Scale the manual editor to feature-length, densely edited projects

Prerequisite: TASK_13. Limit changes to demonstrated bottlenecks and reusable query/render boundaries.

## Review findings (baseline 0c6b8f1)
- `core/model.py` resolves tracks, sources and clips by repeated linear scans; `render/plan.py:_plan_video` scans all clips for each boundary via video_clip_at. _peak_level iterates every audio item at each level-change point. This is acceptable for a small project but becomes quadratic (or worse with track scans) as future tools subdivide films.
- `render/graph.py:_audio_item` generates leading silence and pads each contribution to the entire range before amix. Work grows with item count times range duration, not the amount of audible material. Hundreds of short audio edits should not each process two hours of silence.
- `render/exporter.py:_chunk_ranges` counts item ends rather than peak active inputs per resulting piece. Long overlapping items can exceed the bound; audio-only cut boundaries can produce a piece with zero video frames. Replanning chunks can restart temporal filters and introduce joins. Whole-film FFV1 staging can require enormous disk space (even conservative estimates can refuse otherwise practical 4K exports). The docstring's exact joins claim requires validation after TASK_11/12, not assumption.
- `render/cache.py:render_fingerprint` includes entire composition, clip/link IDs and all used assets for every range, so an unrelated edit invalidates every cached preview; asset identities are concatenated in sorted ID order without explicit ID-to-identity pairs. Main window also drops all stills on every edit. Before assisted editing, prefer local invalidation when it can be proved safe.

## Implement
1. Benchmark first using existing long_project_check plus a deterministic larger project (e.g. 2h, 1k/5k/10k clips, mixed rates, several tracks, no actual full movie encoding). Separate plan, interval query, cache lookup, UI paint and worker latency; report actual measurements, not only complexity. Establish correctness oracle against current small-project queries.
2. Introduce immutable snapshot-scoped indexes only where measured/useful: dictionaries by ID/source key, sorted per-track intervals plus bisect for point/range queries, sweep sorted start/end events for planning video winners and active audio. Respect half-open boundaries and track priority; avoid rebuilding on every scrub. Keep existing Project public API or a thin indexed view; no Qt in core, no database. A correct conservative invalidation on snapshot change is preferable to stale indexes.
3. Replace globally padded per-clip audio graphs with range-/track-local processing: e.g. concatenate only the successive clips and actual gaps on each non-overlapping audio track, mix track-length streams in bounded chunks. Preserve sample positions, fades, and plain sum. Short independent slices must not incur O(N*whole_duration) silence. Keep preview and export on same semantics. Measure FFmpeg resource use; don't sacrifice correctness for speed.
4. Partition large renders using global output frame boundaries and sample-index mapping; enforce actual planned graph complexity (inputs, items, argument length) per piece. Check dense simultaneous overlap; if cannot bound it, produce actionable refusal or use a tested staged mix. Avoid zero-frame pieces. Revalidate chunk joins by decoded content at boundaries; retain atempo/PTS continuity policy from TASK_11/12. Use lossless intermediates only when needed; preflight disk using realistic bounded estimates or a conservative upper bound stated as such, including channel counts and final output. If whole-film intermediate storage is prohibitive, document a safe strategy (bounded batches or streaming to one final encoder) and implement only if tested. Never silently switch to lossy independent chunks with AAC priming gaps.
5. Derive preview fingerprints from relevant resolved plan content, output settings, exact requested indices, renderer version, and explicit asset ID/identity pairs. Ignore labels/selection/link IDs and nonparticipating edits only when the rendered media is provably unchanged. Keep cache bounded and ensure active playback/render pins cache entries; invalidate/reject changed asset identities. Start with conservative fallback where a proof is hard.

## Acceptance
- Property/differential tests indexed vs brute-force query/plan for randomly generated valid projects, including overlaps between tracks, equal endpoints, muted tracks and exact fractions. No semantic changes to existing edits.
- Report scaling for 1k/5k/10k clips; demonstrate improved planning/query growth and responsive 2h timeline. Use operation counts/relative measurements as portable regression checks, not brittle absolute wall-clock tests.
- Stress many short audio clips, 100+ edits and forced chunking, dense audio overlap, very short clips/zero-frame boundary candidates. Assert actual per-piece bound or explicit refusal; decode selected windows around joins and compare reference. Report memory/disk/process usage.
- Changing an unrelated distant clip can reuse an unaffected preview; changing an overlapping clip/stack/settings/source identity invalidates it. Verify no stale still after edit/undo. Cache eviction must not remove active output or user files.
- Keep scope focused; document limitations and measurements. No alignment algorithm.
