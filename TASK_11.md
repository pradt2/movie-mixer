# TASK_11 — Correct audio slicing, sample-rate conversion and mixing

Prerequisite: TASK_10. Review the renderer; do not add automatic synchronisation.

## Review findings (baseline 0c6b8f1)
- **Sample-rate bug:** `render/graph.py:GraphBuilder._audio_item` does asetpts -> atempo -> apad -> atrim=end_sample=item.samples -> aformat=output sample rate. item.samples counts OUTPUT samples, whereas atrim sees the input sample rate. At 44.1 kHz -> 48 kHz, a four-second item requests 192000 input samples (4.354s) before resampling; at 96 kHz -> 48 kHz it retains only two seconds. Concatenated silence and final trim can hide the error in container duration. The existing `test_independent_audio_stream_selection_and_resampling` only listens at 1–2 seconds; it misses both tails and leaks into adjacent material.
- Source_end is computed by the planner but not used to explicitly bound input before tempo conversion. At boundaries, samples from outside the intended source slice can influence the result. atempo is stateful, so independently processing chunks/ranges cannot be assumed sample-identical to continuous output.
- `volume=eval=frame` approximates fades by audio-frame timestamps, not a sample-accurate linear envelope. Current comments overstate exactness; especially important for short fades and subrange renders. Fixed AAC padding tolerance assumes 48 kHz and the validator probes only container duration, so missing/short audio or video can go undetected.

## Implement
1. Establish an explicit per-item audio pipeline: seek/decode the selected stream, trim the intended source interval on its actual sample/time axis, rebase PTS, apply pitch-preserving tempo, convert to the output sample rate/layout with explicit aresample/aformat, then enforce the exact *output* sample count with apad/atrim. Place using integer output-sample offsets, not rounded seconds. Verify actual FFmpeg filter negotiation with integration tests rather than assuming it. Avoid leaking material across source_out; for rounding at a clip edge define and document whether silence or a clamped boundary sample is used.
2. Define expected behaviour when a stream unexpectedly ends early: distinguish a tiny quantisation/tempo padding correction from substantial missing source audio; report/refuse significant truncation instead of disguising it as intended silence. Track actual stream bounds where available.
3. Use sample-accurate fades where feasible (e.g. afade with sample start/count on a globally positioned stream, including range-clipped fades; or a tested per-sample envelope). Keep gain and mixing semantics a plain sum. Document channel remapping and reject unsupported layouts rather than treating side and rear speakers as interchangeable. Keep a clear limitation if exact atempo phase continuity across independently sought ranges is impossible: test tolerances, use bounded preroll/overlap or render contiguous tempo-processed slices once before chunking when necessary. Do not pretend approximate audio is bit-exact.
4. Probe/validate the output streams individually: expected video frame count, audio duration/sample counts with codec-delay tolerance derived from sample rate and codec, layout/rate and dimensions. Use lossless PCM fixtures for exact tests, decoded AAC for delivery tests. Do not infer correctness from format.duration alone. Bump render cache SEMANTICS_VERSION.

## Acceptance
- Generate 44.1, 48 and 96 kHz inputs with distinct tones immediately before/inside/after a nonzero selected interval, render to 44.1 and 48 kHz at rates 1 and 25/24; decoded PCM verifies the complete audible extent, not only its middle, no adjacent-tone leak and correct start/end/gap samples (account for documented tempo/codec transition tolerances).
- Test two staggered clips with different sample rates, overlapping tracks, short fades, nonzero stream origin, range clipped inside a fade, and fractional placement. Verify decoded sample count, RMS/envelope and frequencies at both edges.
- Compare single-pass and forced-chunk output around a long retimed clip crossing a chunk boundary. Quantify allowed deviation, avoid extra silence/priming and document remaining limits. Include source ending earlier than conservative metadata and a malformed/truncated rendered output.
- Existing export and preview tests pass or are deliberately corrected; update docs and report measured errors. No new delivery codec feature.
